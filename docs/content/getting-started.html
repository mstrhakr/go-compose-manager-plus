Run locally

Install the Go version specified in go.mod (currently 1.27.4). Set a temporary bootstrap account without placing its password in shell history:

read -rp 'Admin username: ' APP_BOOTSTRAP_USERNAME
read -rsp 'Temporary admin password: ' APP_BOOTSTRAP_PASSWORD
printf '\n'
export APP_BOOTSTRAP_USERNAME APP_BOOTSTRAP_PASSWORD
make run

Open http://127.0.0.1:8080/, sign in and complete the required password change. Discovery is available on request; Docker inventory is disabled by default and management actions are not connected. Stop the server with Ctrl+C.

Run in Docker

Install Docker Engine and Docker Compose. The example Compose file uses the planned latest image tag, which is not yet published. Until a normal release exists, use the Linux amd64 dev tag for testing instead; it can change and is not a production release. Save the example as compose.yaml, change its image tag to dev, and create a private .env file containing APP_BOOTSTRAP_USERNAME and a strong temporary APP_BOOTSTRAP_PASSWORD. Do not commit the file or place the password in shell history. For example, edit the file privately and replace both placeholders:

APP_BOOTSTRAP_USERNAME=replace-with-admin-name
APP_BOOTSTRAP_PASSWORD=replace-with-strong-temporary-password

Then start the app:

chmod 600 .env
docker compose pull
docker compose up -d
docker compose logs -f

Open http://127.0.0.1:8080/ and complete the forced password change. Compose binds the host port to loopback and stores account/session state in its persistent app-data volume. Remove the bootstrap values from .env after setup and run docker compose up -d --force-recreate to remove them from the container environment. Docker status is disabled by default; management actions are not connected.

Discovery and Docker inventory

Mount a trusted project root into the container and save its in-container path as the discovery root. Requested scans examine direct-child directories. Discovered projects begin inactive; activation grants permission only and does not start or modify containers. Project paths shown in the app are container paths. A read-only project mount prevents writes but is not a read-access sandbox for Compose references outside the project directory.

Docker inventory requires both APP_DOCKER_SOCKET and a socket mount. The app user must have permission to connect: inspect the host socket's numeric group with stat -Lc '%g' /var/run/docker.sock and, if its group has write permission, add that ID under group_add and recreate the service. Inspect socket ownership and mode with stat -Lc 'uid=%u gid=%g mode=%a' /var/run/docker.sock. Docker API access is effectively host-administrative; a :ro socket mount does not make API access read-only. Only grant it inside a trusted security boundary. Snapshots list running and stopped containers but do not provide logs, live metrics or lifecycle operations.

On the Projects and Containers pages, use Customize columns to choose visible columns and restore the defaults. Preferences are saved separately for each view in your browser; the identifying column always stays visible. Without JavaScript, all columns remain visible.

Configuration

The native binary reads exported environment variables, not dotenv files.

In the Compose example, APP_ADDR and APP_DATA_DIR are fixed to the container listener and volume path. Change the Compose file itself if those container paths need to change; APP_PORT controls only the host port.

VariableDefaultPurpose
APP_ADDR127.0.0.1:8080Listen host and numeric port (1–65535)
APP_LOG_LEVELinfodebug, info, warn, or error
APP_DATA_DIR./dataPersistent SQLite state directory
APP_DOCKER_SOCKETunsetOptional absolute Unix socket path for on-demand read-only status; socket access is effectively host-administrative
APP_PUBLIC_URLhttp://127.0.0.1:8080Canonical app origin; remote origin requires HTTPS
APP_TRUSTED_PROXIESemptyComma-separated immediate proxy CIDRs
APP_BOOTSTRAP_USERNAMEunsetRequired with password only for an uninitialized database
APP_BOOTSTRAP_PASSWORDunsetTemporary bootstrap password; remove from deployment env after setup
APP_PORT8080Compose host port only

Bootstrap credentials are used only once; later environment changes do not reset saved credentials. Docker administrators can inspect container environment, so protect the temporary bootstrap values and remove them after first-run setup. Compose persists app state in a dedicated /data volume.

The database is local persistent state, not a supported network-shared or multi-instance database. Back it up consistently before upgrades or moving hosts. If the volume is lost, the app cannot distinguish a genuinely new installation from lost credentials; recovery/reset procedures are not implemented yet.
