Daily commands

Install Go 1.27.4, Node 24, GNU Make, and a C compiler (Go race tests use CGO). On Windows, use an appropriate Make/GCC toolchain or WSL for the local full suite; native Windows behavior is separately checked by CI. Hugo and Docker are optional until working on their surfaces.

make setup       # once: locked npm tools and Playwright browsers
make test        # all Go, JS/unit/API, and desktop/mobile browser tests
make check       # above plus vet, formatting, build, assets, contracts
make fmt         # format Go code
make test-go      # focused race-enabled Go checks
make test-js      # Node unit tests and browserless HTTP tests
make test-e2e     # Chromium, Firefox, WebKit, mobile Chromium
make check-workflows # workflow lint and token/pin policy
make check-security  # npm audit and Go vulnerability analysis
make check-container # Docker build and vulnerability scan
make docs         # default docs build
make docs-contracts # opt-in preview including contracts
make docs-development # opt-in preview including contributor docs
make check-docs   # test public and opt-in site variants

Linux browser system dependencies can be installed with npm exec -- playwright install --with-deps chromium firefox webkit. Run privileged OS installation yourself when your environment requires it. VS Code's default Test task runs make test. No separate test.sh is needed: a wrapper would only delegate to Make, never maintain a second test list.

Playwright starts/stops a dedicated Go server at 127.0.0.1:18080 and refuses to reuse an unrelated existing listener. Two workers bound memory use; tests do not retry failures. Reports and failure traces are local ignored artifacts. Node unit tests use the built-in runner; HTTP and browser tests use Playwright.

Go tests use the standard testing and httptest packages. Add table-driven configuration tests and handler tests near the implementation. For an individual package, run go test -race ./internal/web.

For shorter interactive output, use make check QUIET=1. Each check announces its start and completion; output is captured and printed in full if that check fails. The default remains unchanged. This reduces visible logs, not test runtime. For GitHub progress, make pr-checks watches the current branch's PR, or use make pr-checks PR=9. make run-watch RUN=123 follows a specific Actions run with gh run watch --compact --exit-status. These targets need an authenticated GitHub CLI; PR watch output is the standard gh output and may repeat status lines.

For an opt-in live Docker snapshot check, run CMP_LIVE_DOCKER=1 CMP_LIVE_ACK=/var/run/docker.sock make test-live-docker, replacing the acknowledgement with the exact socket path. It creates a uniquely named disposable Compose container with no host mounts, ports, networks or named volumes, then removes only a verified fixture container and its anonymous volumes. It requires the development image to be present locally; it does not pull, build or prune. It is not part of make check and a crash can leave a fixture behind. Use a disposable daemon when stronger isolation is needed.

The test-only metrics spike can stream read-only stats for one explicitly selected running container for ten seconds, writing only to a temporary tstorage directory. It does not create, start or stop containers:

CMP_METRICS_SOCKET=/var/run/docker.sock CMP_METRICS_CONTAINER=CONTAINER_NAME \
  go test -race -count=1 -run '^TestLiveStatsStorage$' -v ./internal/metricspoc

Select a daemon and container only with their owner's permission. The socket grants host-administrative access even though this test uses a read-only API request. This short single-container test is not a representative resource benchmark, retention implementation or continuously running collector.

UI components

Reusable server-rendered metric, chart and list panels are defined in internal/web/templates/partials/components.html, with their Go view types in internal/web/components.go and shared styles in internal/web/static/foundation.css. Use unique, stable heading IDs for each panel. Prefer the existing panels over copying page-specific markup. The dashboard uses unavailable states until real data is available; sample data exists only in tests/ui-fixture/, not an application route.

The chart's optional Series is a JSON string supplied by the server, automatically escaped by the template. Serialize it with encoding/json rather than concatenating input. Its object has finite numeric min and max values, optional text xLabel and yLabel, and a nonempty series array. Each series has a label, a color from blue, amber, purple, green, or red, and points with strictly increasing numeric x and numeric or null y. Values must lie within the shared range; null separates lines. Callers must choose consistent units, meaningful labels, and an appropriate range. The component does not fetch, aggregate, timestamp, or interpret data; chart freshness and authority remain the caller's responsibility. The chart includes a keyboard-accessible data table, an empty state and an explicit invalid-data error. With JavaScript disabled it reports that chart data cannot be displayed.

List panels render semantic tables and optional native checkboxes; enable Selectable only when a consumer needs selection. Local enhancement provides a scoped select-all checkbox, count and a bubbling list:selectionchange event whose detail.selected contains the selected values. Disabled rows are excluded. Selection is ephemeral and does not authorize or perform any operation. After htmx swaps, controls are reinitialized from the new DOM; consumers own persistence, data refresh and action policy. Inventory filters and ordering are server-rendered GET forms; applying them requests a fresh snapshot and uses counts before filtering. View navigation uses ordinary links and disabled buttons rather than an ARIA tab widget; add real destinations only when their behavior is implemented. With no JavaScript the individual native checkboxes remain usable.

Run npx playwright test tests/e2e/components.spec.js --project=chromium to render the actual templates in a test-only page, with populated, empty, invalid and selectable examples. Browser screenshots are local test artifacts; the fixture is not served by the application.

Dependencies and updates

The auth slice uses third-party Go modules for SQLite, password hashing, server-side sessions and CSRF protection. Use go get module@version and go mod tidy when adding dependencies, and commit both module files. Docker copies both automatically.

Dependabot checks Go modules/toolchain, npm, GitHub Actions references in workflows, and Dockerfile base images. Weekly version updates group minor and patch updates by ecosystem; majors get individual PRs. Security updates use separate minor/patch groups and individual majors; their timing is independent of the weekly version-update schedule. Groups do not cross ecosystems. Review updates rather than automatically merging them. Go starts at 1.27.4 and Hugo at 0.169.0, the latest stable releases checked for this first pass.

When updating Go, align go.mod and the Dockerfile tag/digest. When updating Hugo, update the version and official release SHA-256 in .github/actions/setup-hugo/action.yml; Hugo's binary is not managed by Dependabot. Install that same Hugo version locally from the official release, checking its checksum before running it.

htmx is pinned in package-lock.json and committed under internal/web/static with its license and SHA-256 metadata. After an intentional package update, run npm run assets, review the generated changes, then run make check-assets. A Dependabot htmx PR updates npm metadata, not these committed assets: CI will fail until a maintainer updates the assets in the PR. Never execute PR code in a privileged workflow to do that automatically. Builds do not download browser code from a CDN. Node is not required to run an already-built executable or container.

Dependabot does not monitor every version embedded in arbitrary shell or JS: GoReleaser and Hugo release URLs/checksums, govulncheck and actionlint invocations, Buildx versions, and the Trivy image tag/digest in the scanner script need manual version checks and reviewed updates. Node 24, Go versions in prose and other duplicate pins also need coordination; a Docker or go.mod update does not rewrite them all. Check upstream releases and independently verify downloaded checksums. Direct Action pins are not a guarantee about transitive Actions or downloads.

Documentation

Content lives in docs/content/. Architecture, development and deployment pages are excluded from the default public site and enabled by hugo.development.toml; contracts are independently opt-in. Add any new contributor-only page to the exclusions in hugo.toml before adding it to the content directory. make check-docs builds and checks all four combinations in temporary directories. Existing pages use HTML with TOML front matter; Hugo also supports Markdown pages. Add a title and weight to include a page in navigation. Layouts and CSS are local, avoiding theme/submodule drift. CI builds the site with a project subpath to check GitHub Pages compatibility.

Continuous integration

Protect main; use short-lived branches and squash PRs with Conventional Commit titles. No permanent dev branch, mandatory second reviewer, or local commit hook. The optional VS Code extension assists authoring; CI checks the PR title and the squash defaults use it. Maintainers must preserve that checked message on merge.

CI detects changed surfaces and runs only relevant read-only jobs. Unknown paths/shared tooling run broadly; failed detection or cancelled/failed checks fail the final CI gate. Contract-only edits skip app jobs unless mixed with code. When contract publication is enabled, those edits also validate the docs build.

Native Go CI covers Linux x64, Windows x64, macOS x64 and macOS ARM64. Cross-compiling releases is not native execution evidence. Browser tests on Linux exercise Chromium, Firefox and WebKit; WebKit is not a native Safari run, and mobile emulation is not a physical-device test.

PR jobs never receive publishing secrets or write scopes. Privileged events do not execute PR source; no public-PR self-hosted runners or cross-trust caches. Dependency scans run on relevant changes and a schedule. Protected-main CodeQL has security-report write scope, not PR access or package publication rights.

See the contract guide before behavioral changes. Structure checks do not approve a requirement; report actual executed checks and remaining gaps.
